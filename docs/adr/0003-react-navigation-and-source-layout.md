# ADR 0003: React Navigation and source organization

Date: 2026-11-21
Status: Approved by the owner in chat; source migration applied; runtime verification pending.

## Decision

Replace Expo Router with React Navigation 7, retaining strict TypeScript, Expo SDK 58, local Android builds, SQLite and the existing privacy boundaries. Follow the organizational categories of [at-byahe](https://github.com/saintmarkgrotes/at-byahe/tree/main/src). Reference folders are copied as organizational categories, not travel features or its AsyncStorage implementation.

The owner explicitly authorized replacing Router and clarified that Pandecoco authorizes direct edits for this specific chat step. This direct clarification supersedes the older stopping-word wording in the chat-step instruction file. No instruction files were overwritten. The owner retains all test/build/runtime execution.

## Ownership

- `App.tsx` composes providers, native safe areas and NavigationContainer; `index.ts` registers the Expo root component.
- `navigation/` owns typed root/tab stacks, tab definitions and deep-link mapping.
- `screens/` assembles a view and a controller hook.
- `components/` renders data and callbacks. Platform presentation primitives may use display-only hooks, such as a scoped wake-lock component.
- `hooks/` owns screen state, form flow, effects and navigation actions.
- `context/` exposes the database-backed profile projection and service operations; it is not a second mutable database.
- `state/profile/` keeps pure validation, application service/port, SQLite adapter and composition in separate files. `state/timer/` is the pure timer engine; `state/db/` holds native checkpoint/diagnostic adapters.
- `constants/` owns theme and localized English strings. `utils/` is reserved for shared pure helpers. `maps/` is an empty reference-layout placeholder, not a feature.

## Compatibility boundary

Preserve Android package `com.jwtimer.feasibility`, scheme `jwtimer-prototype`, profile/timer database filenames, preference key, saved record format, revision checks, migration SQL/checksum input, and pure timer/profile domain modules. No database migration or new user-data format is introduced by this refactor.

Preserve logical deep-link paths: `/meetings`, `/assignments`, `/timer`, `/settings`, `/setup/profile`, `/settings/profile`, `/timer/prototype` and `/diagnostics`. The Home path remains `/`. Unconfigured devices can only enter profile setup; profile presence is not a sharing/publishing grant.

Cold detail links receive a Main parent route. Any no-history profile exit uses a removal action so unsaved changes can be confirmed. PracticeTimer has one stable route identity, and fullscreen presentation effects require route focus; warm links must not create competing checkpoint writers or let a covered timer consume Back.

The native app binary/configuration has not been regenerated by the agent. The next owner build must run Expo Android prebuild before installation. Do not infer native or navigation success from source inspection.

## Forward path and rollback

The package entry is `index.ts`, React Navigation 7 is directly declared and locked, and the Expo Router plugin/dependency is removed. The old `app/` tree and remaining source owners are archived under ignored `.refactor-backups/legacy/`. The complete pre-change source/config/package rollback ZIP is `.refactor-backups/2026-11-21-before-react-navigation.zip`.

For rollback, extract the ZIP into a separate folder and compare/restore the source and matching package/config files deliberately; restore the matching lockfile and reinstall dependencies. Never treat uninstalling the Android app or clearing its data as a source rollback. No installed app data was read, altered or deleted by the agent.
